## Introduction

The workshop "EcStatic Magic" was focused on teaching how to build simple websites using something called static site generation. this may sound technical, but the main idea is pretty straightforward, instead of building complex websites that constantly change you create a website made of pre built pages that are fast and easy to manage.

This workshop was especially useful for beginners as it explained both what static sites are and how to actually make one using tools like Jekyll and GitHub Pages.

Even if someone has never built a website before, the session showed that it's possible to create a clean, professional site with minimal to zero coding experience.

⸻

## What Are Static Sites

A static website is made of fixed files (like HTML pages) that are created before the site is published. When someone visits the site, they are just loading those pre made pages.

A dynamic website, on the other hand, builds pages in real time using databases and server side code (like social media apps or online stores).

- **Static site** → pages already exist
- **Dynamic site** → pages are created when you visit

Static sites are:
- Faster (no waiting for data to load)
- More secure (fewer things can break or be hacked)
- Easier to maintain (no databases or servers needed)

Static Site Generators:
It takes simple text files (written in Markdown which is almost basic english) and turns them into a full website

## Why Use Static Sites?

The workshop explained several reasons why static sites are useful:

### 1. Speed

Since everything is pre-built, pages load almost instantly.

### 2. Security

There is no database or backend system, which reduces the risk of attacks.

### 3. Flexibility

You control how everything looks and works.

### 4. Preservation

Static sites don't depend on constantly updating software, so they are easier to keep online long-term.

### 5. Lower Resource Usage

They require less computing power, which makes them more efficient.

## Tools Introduced in the Workshop

The session introduced several tools that make building static sites easier:

### Jekyll

Jekyll is a static site generator. It takes simple text files (written in Markdown) and turns them into a full website.

- Setup guide: https://jekyllrb.com/docs/step-by-step/01-setup/

⸻

### GitHub Pages

GitHub Pages is a free hosting service that lets you publish your website online directly from a GitHub repository.

- Official site: https://pages.github.com/

- Beginner guide (how to make a site): https://pages.github.com/

This means you don't need to pay for hosting or manage servers. You just upload your files and your site is live.

⸻

### Collection Builder

Collection Builder is a tool designed for creating digital collections, such as archives or galleries.

- Try CollectionBuilder: https://lib-static.github.io/models/ 

It allows you to organize items using metadata (like titles, dates, and descriptions), which is especially useful for research projects.

## How This Connects to "Reading like a Computer"

Even though this workshop focused on websites, it connects closely to what we are doing in class.

### 1. Working with Corpora

In class, we work with large collections of texts (corpora). Static sites can be used to store and display those collections. (Literally this post you're reading now)

Each page can represent:
- A document
- A dataset
- A text with analysis (All the assignments we are doing in the class too)

⸻

### 2. Distant Reading

We discussed how it's impossible to read everything (as mentioned in "So Many Books, So Little Time"). Instead, we use computational methods to analyze many texts at once.

Static sites help by:
- Organizing large datasets
- Presenting results clearly
- Allowing users to explore data

⸻

### 3. Tools Like Voyant and R

We used tools like Voyant and R to analyze text using:
- Word clouds
- Most Frequent Words (MFWs)

Those tools focus on analysis, while static sites focus on presentation.

So the work flow becomes:

**Text → Analysis → Website**

⸻

### 4. Scaling Up Projects

As we move into topics like TF-IDF, stylometry, and entity extraction, we start working with more complex data.

Static sites provide a way to:
- Display results
- Compare texts
- Share findings publicly

## Reflection

Before this workshop and my core, building a website seemed like something that required a lot of technical knowledge. But this session showed that with the right tools, it's actually manageable and may even be considered simple.

The most interesting idea was that websites don't always need to be a very complex thing or dynamic to be effective. For many academic or research based projects a static site is actually a better option because it is faster, simpler, and easier to maintain.

It also made it clear that creating a project is not just about analyzing data, but also about presenting it in a way that others can understand.
